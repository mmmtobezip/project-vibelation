# VIBELATION

현업의 개선 요청을 자료 → 레거시 분석 → Mock 협의 → 검토 리포트로 연결하는 한국어 인터랙티브 Mock입니다. React 19 + TypeScript + Vite 6으로 구현했습니다.

## 실행

Node.js 24 권장. 의존성 설치는 잠금 파일을 유지합니다.

```sh
npm ci
npm run dev
npm run build
```

Vite base는 `/project-vibelation/`이며 HashRouter를 사용합니다. 개발 서버는 기본 5173 포트입니다.

## 시연 흐름

1. 요청 작업실에서 대화 샘플을 확인하고 **화면 구체화**를 누릅니다. HTML 탭은 코드 입력과 sandbox 미리보기를 지원합니다.
2. **레거시 분석 → 영향도 분석**을 누르고 자원별 현재 구조·변경 제안·검토 의견을 확인합니다.
3. **Mock 화면 → 시스템 Mock 생성**에서 현재 시스템/적용 제안을 비교합니다.
4. **협의사항 도출**에서 리포트 탭을 확인한 뒤 두 검토 항목을 체크하고 등록합니다.
5. 과거 검토 이력에서 제목 검색, 상세 조회, Markdown 다운로드를 확인합니다.
6. 팀 진행 현황에서 담당자·상태·제목으로 필터링합니다. SR 행을 열어 표준 기한, 등록일 조정 제안, 특이 SR 메일 초안을 확인합니다.

상단 4단계는 자유롭게 반복할 수 있습니다. 요구사항·협의 의견 수정 시 버전이 증가하고 확인 체크가 해제되며, 이전 분석과 Mock은 재검토 대상으로 표시됩니다. 최신 버전의 자료 구체화·분석·Mock이 완료되어야 리포트 등록이 가능합니다.

## 데이터와 구현 범위

- 화면은 제공된 MyPOSCO 참고 디자인의 블루·밝은 배경·탭·카드 구성을 반영합니다.
- 다운로드 센터의 분석 경로는 제공된 Front/Back ZIP의 파일 구조를 참고했습니다. 변경 제안, MD 요구사항과 공수는 고정된 **시연용 시나리오**이며 입력에 대한 실제 AI 분석은 아닙니다.
- HTML은 sandbox와 CSP로 스크립트·외부 통신을 차단해 표시합니다. PPT는 파일명 선택만 지원하며 파싱하지 않습니다.
- SR 40건은 제공 Excel 데이터를 사용합니다. SR 번호 중복을 덮어쓰지 않고 행별 키로 구분합니다.
- 표준 공기는 유지보수 SR의 FP MM 구간표를 사용합니다. RR/ITSM은 유형 기준 확인 전 판정을 보류합니다. Agent의 MD 예상 공수와 FP MM은 별개입니다.
- SR 시연 기준일은 **2026-10-14**로 고정했습니다. 임박은 해당 기준일 이후 2근무일 이내입니다. 임박·완료일 초과는 미완료 건에만 적용합니다.
- 등록일 다음 근무일부터 계산하며 주말·코드에 명시된 2026년 대한민국 공휴일/대체공휴일을 제외합니다. 회사 휴무·추가 임시공휴일 및 다른 연도는 별도 연결이 필요합니다. 등록 당일 산입 방식은 회사 규칙과 최종 대조해야 합니다.
- 요청완료일이 표준 기한보다 늦으면 등록 일정에 대한 표준 공기 경고를 표시합니다. 완료 건에는 실제 완료일이 없으므로 실제 지연 완료를 판정하지 않습니다.
- 등록일 조정은 제안만 제공하며 실제 SR 시스템의 날짜·상태를 변경하지 않습니다. 요청완료일이 비근무일인 경우에는 조정일을 담당자가 추가 확인해야 합니다.
- 실제 ZIP 파일 다운로드, AI/PPT 처리, 메일·Teams 발송, FP 견적 업로드, 인증 및 다중 사용자 저장은 미연결입니다. 선택 다운로드는 시연 안내만 제공합니다.
- Google Fonts는 선택 사항이며 접근 불가 시 시스템 폰트로 표시됩니다.

브라우저 저장 키는 `vibelation.workspace.v2` 및 `vibelation.reports.v2`입니다. 이전 v1 데이터는 그대로 보존하며 자동 이전하지 않습니다. 실제 개인정보·민감한 소스는 입력하지 마세요. 브라우저 저장소는 팀 공용 서버가 아닙니다.

## 검증

```sh
npm run build
node --experimental-strip-types --test tests/calendar.test.mjs
```

개발 중 Chromium으로 단계 생성·확정·등록, 리포트 검색, SR 상세·메일 초안, 새로고침 복원 및 모바일 가로 넘침을 검증했습니다. 실제 외부 서비스 연동 검증은 포함하지 않습니다.

## 팀 공유 · GitHub Pages

`main`에 반영하면 `.github/workflows/pages.yml`에서 빌드하고 Pages에 배포합니다. 저장소의 **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**여야 합니다.

- 서비스 주소: https://mmmtobezip.github.io/project-vibelation/
- 화이트 Mock 고정 파일: https://mmmtobezip.github.io/project-vibelation/mock-white.html

`public/mock-white.html`은 팀 리뷰용 독립 HTML 스냅샷입니다. 서비스 소스를 수정해도 자동으로 갱신되지 않습니다. 화이트 Mock을 새 버전으로 교체하려면 새 빌드의 JS/CSS를 인라인한 HTML로 해당 파일도 갱신해야 합니다.

공유되는 것은 같은 화면과 샘플 데이터입니다. 입력·등록 이력은 각자의 브라우저에 저장되므로 팀 공용 데이터 저장을 의미하지 않습니다.
